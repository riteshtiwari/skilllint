# Human Writing Rules

Use this file to evaluate whether text in commits, docs, UI copy, or code comments was written by a person or generated by a bot.

---

## The Core Test

Read the sentence aloud. Would a person actually say it in conversation? If it sounds like a customer service script, a corporate email, or a chatbot response, it fails.

---

## Words and Phrases That Flag Bot-Generated Text

Ban these outright. No exceptions.

**Affirmation openers:**
- "Certainly!", "Absolutely!", "Of course!", "Sure!", "Great question!"
- "I'd be happy to", "I'm glad you asked", "I'm excited to share"

**Filler transitions:**
- "In conclusion", "In summary", "To summarize", "As a result,"
- "It is worth noting that", "It is important to mention that"
- "First and foremost", "Last but not least"

**Bot vocabulary (replace with plain words):**
- "leverage" → use
- "utilize" → use
- "delve into" → look at, go through
- "dive into" → start, begin
- "explore" (used metaphorically) → look at
- "seamlessly" → anything else
- "robust" → solid, strong, reliable
- "comprehensive" → thorough, complete, full
- "streamline" → simplify, speed up
- "cutting-edge" → anything else
- "state-of-the-art" → anything else
- "harness" (metaphorical) → use
- "empower" → let, allow, help
- "revolutionize" → change, improve
- "game-changing" → delete it
- "transformative" → delete it
- "intuitive" → delete it (show instead)

**Emoji used as decoration or emotional signal:**
- ✅ ❌ 🚀 💡 🎯 🔥 ✨ 🎉 👇 👆 → none of these in commits, UI text, or docs
- Emoji are only acceptable in places where they serve a functional role (e.g., status indicators that users see)

**Lists where prose would do:**
- If a sentence starts with three bullets that each contain one short phrase, it should be a sentence instead
- Bad: "This update: • Fixes the bug • Improves performance • Adds logging"
- Good: "Fixes the bug, tightens the fetch loop, and adds logging for failed parses."

**Passive voice in instructions or commit messages:**
- "The file should be saved" → "Save the file"
- "Users are informed" → "Users see"
- "Errors are handled" → "Handles errors"

**Hedging:**
- "This might potentially cause", "This could possibly lead to" → say what it does
- "It appears that", "It seems like" → say what it is

## Structural Patterns That Read as Bot-Generated

**The three-part list conclusion:**
Any paragraph that ends by listing three things you just said, but in bullet form, is bot output.

**The symmetric paragraph:**
Opening sentence restates the question. Middle sentences answer it. Closing sentence restates the answer. This is a template, not writing.

**Excessive capitalization of concepts:**
"The System", "The Architecture", "The User Journey" — writing in title case for common nouns signals a bot treating every noun like a proper noun.

**Headers every two sentences:**
If every paragraph has its own `##` heading, the document was generated, not written. Human writers use prose to connect ideas. Headers are for navigation, not decoration.

**Over-enumeration:**
A list of eight items where three would do is bot output. Humans make choices. Bots list everything.

## What Human Writing Actually Looks Like

- Sentences vary in length. Short ones land hard. Longer ones carry nuance and context without feeling padded.
- It takes a position. "This is the wrong approach" instead of "There may be some considerations worth exploring."
- It uses contractions naturally. "It doesn't" not "It does not."
- It omits what the reader already knows. It doesn't re-explain context just established.
- It sounds like the person wrote it, not a template they filled in.
- Specific numbers and names over vague categories: "three API calls" not "multiple API calls."
- Active voice by default.
- First person is fine. "I changed X because Y" is better than "X was changed due to Y."

## Commit Message Rules

Commits must:
- Start with an imperative verb: Fix, Add, Remove, Refactor, Update — not "Fixed", "Adding", "This commit changes"
- Describe what changed and why, not what files were touched
- Be under 72 characters on the first line
- Use plain prose for the body — no bullets, no emoji, no headers
- Not contain "Co-Authored-By: Claude" or any AI attribution
- Not contain "Generated by", "Created with AI", or similar

Commits must not:
- Mention Claude, Anthropic, AI, or any model name
- Use 🤖 or any emoji
- Start with "This commit...", "Here we...", "We have..."
- Pad the message with obvious information ("Changed the code to make the feature work")

Good: `Fix FileReader error handler missing from handleFile callback`
Bad: `Updated the file handling code to add error handling support ✅`
Bad: `fix: add error handling` (too vague, no context)
